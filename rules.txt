Showdown 1 其实可以拆成两层：牌怎么比大小，以及比赛怎么算赢。

牌的规则非常简单。每一手里，你有一个 your_number，桌面有一个 community_number，对手也有自己的数字。最关键的规则是：

如果你的数字等于 community number，你就组成了 pair，而任何 pair 都比任何没有 pair 的牌强。

比如桌面是：

community_number = 5

你拿：

your_number = 5

那你就是 pair。

哪怕对手拿的是 13，只要他不是 5，你还是赢，因为：

pair > any non-pair

如果你和对手都没有 pair，那就非常直接：

数字大的赢

例如 community 是 5：

你 = 11
对手 = 8

两个人都不是 pair，所以你赢。

如果最后牌力完全一样，就 split the pot，也就是两个人平分底池。

然后比赛形式是 1v1，你只面对一个官方 bot。一场 match 固定打：

100 hands

每次提交/attempt，就是完整地跟这个 bot 打这一场 100 手。

你真正的目标不是“100 手里赢多少手”，而是看最终的：

chip_delta

简单理解就是：

最终筹码 - 初始筹码

Showdown 1 的满分条件是：

chip_delta >= +10

就拿：

300 points

所以假设你初始是 200 chips：

最后 210 → +10 → 满分
最后 225 → +25 → 也是满分
最后 207 → +7 → 没达到 clear 条件
最后 180 → -20 → 没达到

所以这关并不要求你把 bot 打爆。只需要最终比开始时多赚至少 10 chips。

还有一个非常重要的地方：bet size 没有 cap。也就是说一次可以下注得非常大，因此每次 attempt 的结果可能波动特别大。规则自己也提醒你：

一次坏结果不要立刻重写整个策略，因为只记录你的 best attempt。

比如同一套策略可能出现：

Attempt 1: -35
Attempt 2: +6
Attempt 3: +18
Attempt 4: -12

那你的 best attempt 就是 +18，已经超过 +10，所以这一 phase 就 clear 了。

另外 table_rule 在 Showdown 1 的 100 手中一直都是：

standard

也就是说不会打一半突然换规则。

所以你可以把 Showdown 1 最简化成一句话：

写一个 betting bot，和官方 bot 打 100 手；pair 最大，否则数字大的赢；最终净赚至少 10 chips 就满分，而且只看你最好的一次 attempt。

这也解释了为什么你代码里会有 preserve 的想法：比如第 70 手你已经：

chip_delta = +17

那其实你已经超过通关线了。这时候理论上就没必要拿一个一般的牌去跟对面打一个 100 chips 的大底池，因为：

+17 → 输一个大 pot → -30

反而把已经到手的通关状态送掉了。

所以 Showdown 1 不完全是“尽量赚最多钱”问题，而是“100 手结束时尽可能保证 ≥ +10”的问题。 这个区别对策略很重要。

Showdown 2 和 1 最大的区别，不是 betting 规则变复杂，而是“牌的胜负规则被隐藏了，而且每一段可能不一样”。

Showdown 2 一次 attempt 一共有 4 个 leg，每个 leg 是一场独立的小比赛：

Leg 1: 40 hands
Leg 2: 40 hands
Leg 3: 40 hands
Leg 4: 40 hands

所以一次 attempt 总共最多会打 160 hands。

而且每个 leg 都会重新开始：

starting stack = 200
chip_delta = 0
hand_number = 1
recent_hands = 清空

也就是说，前一个 leg 输了多少筹码不会带到下一个 leg。这是非常重要的。

评分也变了

Showdown 1 是整场 100 hands 最终：

chip_delta >= +10
→ 300 pts

Showdown 2 则是每个 leg 单独算：

某个 leg 最终 chip_delta >= +25
→ 100 pts

四个 leg 分数累加：

过 1 个 leg → 100
过 2 个 → 200
过 3 个 → 300
过 4 个 → 400

而且不要求四个都过。

所以这意味着策略目标已经变成：

每 40 手之内，想办法在这个 table rule 下赚到至少 +25。

真正的新东西：table_rule

Showdown 1：

table_rule = standard

你知道规则就是：

pair > non-pair
否则数字大的赢

但 Showdown 2 每个 leg 有自己的：

data["table_rule"]

比如官方举的只是形式上的例子：

chalcedony

这个字符串本身没有任何语义。

也就是说你不能看到：

table_rule = "chalcedony"

然后根据英文意思猜规则。

它只是一个codename / ID。

类似：

Rule A → "abc"
Rule B → "xyz"
Rule C → "qwe"

真正重要的是：

同一个 codename 永远对应同一个隐藏胜负规则。

不仅本次 attempt 一样，而是：

所有 retry
所有 match
甚至以后 phase

只要看到同一个 table_rule，它的 showdown rule 就一定一样。

这就是 Phase 2 最核心的 exploitable 信息。

什么叫 hidden table rule？

官方明确说：

Only the showdown changes.

所以这些都不会变：

betting
blind
position
bet sizing
protocol

唯一改变的是：

最后两个人亮牌后，到底谁赢。

例如标准规则以前可能是：

你的数字 10
对手数字 8
community 3

→ 10 > 8
→ 你赢

但某个隐藏 rule 下：

10 vs 8

不一定还是你赢。

官方举的例子是：

odd numbers beat even numbers, within each group higher wins

但是它特别说明：

这个规则不在比赛中。

只是告诉你真实 rule 大概会是这种性质：

改变数字之间的强弱关系

所以不能把 odd/even 写进代码。

最关键的一句话

官方写的是：

The same number can be a monster under one rule and worthless under another.

这个非常重要。

假如你拿：

your_number = 12

在标准规则下非常强。

但假设隐藏 Rule X 的真实关系导致 12 很弱，那么：

12

可能根本不能按照原来的 equity ≈ 很高 来打。

所以你 Showdown 1 现在这个：

calculate_equity(your_number, community_number)

不能直接用于 Showdown 2 的所有 table_rule。

因为它默认：

pair 最大
然后按数字大小

而 Phase 2 就是在故意破坏这个假设。

那我们怎么知道隐藏规则？

这应该就是 Phase 名字：

Reading the Table

真正要你做的事情。

你没办法直接问服务器：

chalcedony 是什么规则？

但是每打完一些 hand，你会收到：

recent_hands

里面有类似：

{
    "community_number": 7,
    "winners": [1],
    "shown_numbers": {
        "0": 12,
        "1": 5
    }
}

这就相当于给你一个实验结果：

在这个 table_rule 下：

community = 7
12 对 5

结果：5 赢

那你就可以得到信息：

这个规则绝对不是简单的 higher-number-wins。

再收集多几个 showdown：

12 vs 5 → 5 wins
8 vs 5 → 5 wins
5 vs 3 → 5 wins
...

慢慢就能推断：

这个 rule 下到底哪些数字强。

所以 recent_hands 在 Phase 1 主要是：

看对手 bluff 不 bluff。

到了 Phase 2，它多了一个更重要的作用：

反推 table_rule。

还有一个非常关键的设计

虽然：

recent_hands 每个 leg 都会 reset

但是：

table_rule mapping 永远固定

这意味着：

第一次 attempt

你可能花很多手研究：

Rule "foo" 到底是什么？

最后只赚了 +5，没有拿到 100 分。

但你已经知道：

foo ≈ 某种规则

然后第二次 retry 的时候，leg 顺序和 rule 完全一样。

官方明确说：

The leg order and each leg's rule are identical on every retry — only the cards change.

也就是说：

Attempt 1:
Leg 1 → Rule A
Leg 2 → Rule B
Leg 3 → Rule C
Leg 4 → Rule D

Attempt 2:
Leg 1 → Rule A
Leg 2 → Rule B
Leg 3 → Rule C
Leg 4 → Rule D

Attempt 3:
还是一样

只有发的牌不同。

这才是 Showdown 2 最大的突破口。

你不是每次重新破解规则。

而是可以：

Attempt 1：学习规则
Attempt 2：利用规则
Attempt 3：继续优化

甚至如果你的 server 一直活着、Python global variables 不重启，理论上还可以让程序自己跨 match 记忆学到的信息——这个我们后面需要确认 evaluator 的实际运行方式，再决定能不能利用。

对手还有一个信息

四个 leg：

The same opponent plays all four legs and plays the same way throughout.

所以：

Leg 1 的 Gaston
Leg 2 的 Gaston
Leg 3 的 Gaston
Leg 4 的 Gaston

实际上是同一种 bot betting strategy。

但对手名字：

Gaston / Alice / ...

每次 attempt 会随机重新取。

所以名字没有意义：

if opponent_name == "Gaston":

这种绝对不要写。

真正能学的是：

这个 opponent 多 aggressive
什么情况下 bet
什么情况下 fold

而这个 betting style 四个 legs 都一致。

只是 recent_hands 官方不给你跨 leg 保存，所以如果我们想利用跨-leg opponent profile，需要我们自己的代码维护。

所以 Showdown 2 本质上是在考三个东西

我会把它理解为：

第一层：Poker / betting
    ↓
什么时候 fold/call/raise

第二层：Rule inference
    ↓
通过 showdown 结果反推出当前 table_rule

第三层：Memory
    ↓
记住 codename → rule 的对应关系
下一次再遇到直接 exploit

而且目标从 Showdown 1 的：

100 hands → +10

提高到了：

40 hands → +25

所以 Phase 2 明显要求更主动地 exploit hidden rule，单靠 Showdown 1 那种普通 pot-odds 策略，大概率不够稳定。

你现在最值得做的下一步其实不是马上改 betting threshold，而是先设计一个东西：

table_rule
    ↓
观测 showdown
    ↓
学习「1~13 每个数字到底有多强」
    ↓
根据学出来的 ranking 重新 calculate_equity

这个才是 Showdown 2 的核心。
